# ZeroLite 1.3.7

The `zeroclaw` CLI on the same upstream base as 1.3.6, ZeroClaw **v0.9.0**
(`6c78ba59b`). This release makes the SQLite memory backend find Chinese,
Japanese and Korean text, stops one-character messages from recalling
unrelated memories, and fixes the web chat's tok/s meter for tool-only
requests. No config or session-store migration. The memory store's
full-text index is converted once, automatically, on first open (see below).
Platforms: Windows x64, Linux x64, Linux arm64. No macOS build.

## Before you upgrade

- **Upgrading from 1.3.3?** Run `zeroclaw config migrate` once (config
  schema version 4), as described in the 1.3.4 notes.
- **The memory index is converted on first start.** Opening `brain.db`
  rebuilds its full-text index (`memories_fts` and its triggers) in a
  per-character form; the memory rows themselves are not touched. It takes
  well under a second for tens of thousands of memories and runs once.
  Back up `brain.db` first if you may roll back.
- **Rolling back to 1.3.6 or older** after the conversion: older binaries
  and the `sqlite3` CLI cannot write to the converted store
  (`no such function: zerolite_fts_text`). Drop the triggers `memories_ai`,
  `memories_ad`, `memories_au` and the table `memories_fts`, start the old
  binary (it recreates its own index) and run `zeroclaw memory reindex`; or
  restore the backup.

## Memory recall for CJK text

- **Chinese, Japanese and Korean words are found by the full-text index.**
  The index makes every CJK character its own token, and queries are
  expanded into two-character windows. A memory `我上周决定用 Rust 重写召回层`
  is now found by `召回`, `上周` and by the sentence
  `你上周说的那个方案怎么样了`. Before, a run of CJK text was one token:
  a word inside it was found only by the LIKE fallback, and a question
  sentence found nothing.
- **Mixed letters and CJK characters pair up:** `A股`, `T恤`, `3月` are
  searchable terms, and `A股行情` searches `A股`, `股行`, `行情`.
- **Better ranking on the LIKE fallback.** When the full-text stage finds
  nothing, the fallback searches the same terms and scores each memory by
  how many of them it contains, instead of a flat 1.0.
- English recall is unchanged, except that one-letter or one-digit terms are
  no longer searched (`plan b` searches `plan`).

## Two-character minimum for recall

- **A query needs a term of two or more letters, digits or CJK
  characters.** `的`, `好`, `是`, `a` or `c++` used to match unrelated
  memories at full score. Now:
  - `memory_recall` answers `No memories found. A query needs at least one
    term of two or more letters, digits or CJK characters.` without
    searching;
  - a chat message such as `好`, `对` or `是` injects no memory context into
    the turn;
  - the SQLite backend returns nothing for such a query and does not embed
    it.
- The rule is length, not a stopword list: `好的`, `是的`, `ok` still
  search.
- `memory_recall` with no query or a bare `*` still lists recent memories.

## Web chat

- **The tok/s meter bills tool-only requests.** A request that only calls
  tools and streams no text is now measured against its own duration, and
  text arriving after a request's usage report (a non-streamed final
  answer, a notice) no longer skews the reading. The meter appears after
  2 s of stream instead of 4 s.

## Repository

- Upstream assets the fork does not ship are removed: container images and
  compose files, package-manager manifests and installers, the desktop app,
  the Raspberry Pi deploy kit, and upstream community config and CI/release
  scripts. Crate metadata points at `iintothewind/zerolite`. The released
  binaries are unaffected.

## Install

| Platform | Asset |
|---|---|
| Windows x64 | `zerolite-1.3.7-x86_64-pc-windows-msvc.zip` |
| Linux x64 | `zerolite-1.3.7-x86_64-unknown-linux-gnu.tar.gz` |
| Linux arm64 | `zerolite-1.3.7-aarch64-unknown-linux-gnu.tar.gz` |

Each binary carries the web dashboard and the WASM plugin host
(`zeroclaw plugin list`). Replace the binary and restart the service.
