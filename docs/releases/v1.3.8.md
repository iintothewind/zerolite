# ZeroLite 1.3.8

The `zeroclaw` CLI on the same upstream base as 1.3.7, ZeroClaw **v0.9.0**
(`6c78ba59b`). This release adds a reasoning-effort slider to the web chat,
DeepSeek and Qwen (behind LiteLLM) compatibility for OpenAI-compatible
aliases, a `deepseek` web-search route, and two `session_search` options.
No config, session-store or memory-store migration.
Platforms: Windows x64, Linux x64, Linux arm64. No macOS build.

## Before you upgrade

- **Upgrading from 1.3.3?** Run `zeroclaw config migrate` once (config
  schema version 4), as described in the 1.3.4 notes.
- **DeepSeek aliases now always receive the configured
  `[runtime] reasoning_effort`**, and an alias `think` (or
  `[runtime] reasoning_enabled`) is sent as `thinking.type`. Check both
  settings if a DeepSeek alias should not reason.
- **`custom` aliases with `think` set now send it** as
  `chat_template_kwargs.enable_thinking`. An explicit
  `chat_template_kwargs.enable_thinking` in the alias still wins.

## Web chat: reasoning-effort slider

- **A chip left of the context ring opens a stepped slider** with the
  levels `auto / off / low / medium / high / xhigh / max`. It is shown on
  the operator chat for every agent.
- **`auto` is the default and sends no effort:** the turn runs with the
  configured behavior, exactly as before this release. Other levels are
  sent with each message and apply to the whole turn, tool calls included.
- **The choice is not saved.** It lives in the page and resets to `auto`
  on reload and when the agent switches model.
- **Levels by provider.** Each provider maps the level to its own request
  shape and offers only the levels it can carry:

  | Provider / model | Levels | Sent as |
  |---|---|---|
  | Claude 4.7 and later (Anthropic) | all | adaptive `thinking` + `output_config.effort`; `off` sends no thinking |
  | Older Claude (Anthropic, Bedrock) | `auto off low medium high` | thinking budget 2,048 / 8,192 / 16,384 tokens |
  | DeepSeek | all | `reasoning_effort` + `thinking.type` |
  | OpenAI Responses, Azure (reasoning models) | `auto low medium high` | `reasoning_effort` |
  | Codex | the levels the model takes unchanged | `reasoning.effort` |
  | Any other OpenAI-compatible model | all | `reasoning_effort` (`off` → `"none"`, or `enable_thinking: false` on a `think` alias) |

- **New alias key `reasoning_levels`** (OpenAI-compatible aliases) lists
  the levels a backend accepts, e.g. `reasoning_levels = ["low", "high"]`;
  the slider then offers exactly these plus `auto`.
- **An unsupported level falls back to `auto` without an error.** When an
  OpenAI-compatible endpoint answers a request carrying the level with an
  error status (other than 401, 403, 429), the request is sent again
  without it, the rest of the turn runs without it, and the slider returns
  to `auto` when the turn ends. Every level stays selectable.
- **Not detectable:** a backend that accepts the parameter and ignores it,
  and an error that arrives after a stream has started.
- Scoped (non-admin) chat has no slider.

## Providers

- **DeepSeek endpoints** (the `deepseek` family, or any alias whose host is
  `api.deepseek.com`):
  - always receive the configured `reasoning_effort`; `xhigh` is sent as
    `max`;
  - map `think` / `[runtime] reasoning_enabled` to
    `thinking: {"type": "enabled" | "disabled"}`; an explicit
    `provider_extra.thinking` wins;
  - always send `reasoning_content` on assistant tool-call history;
  - read the context window from `GET /models`.
- **Interrupted replies are errors.** A chat-completions `finish_reason` of
  `insufficient_system_resource` or `aborted` is reported as a provider
  error instead of a finished reply; partial tool calls are dropped.
- **Qwen and other chat-template models behind LiteLLM.** `custom` aliases
  send their own `think` as `chat_template_kwargs.enable_thinking` (vLLM,
  SGLang and llama.cpp ignore a top-level `enable_thinking`), and probe
  `GET {uri}/models` for a context window, reading LiteLLM's
  `max_input_tokens`.

## Tools

- **`web_search` route `deepseek`** (DeepSeek Search API), keyed by
  `[web_search] deepseek_api_key`.
- **`session_search` takes `ignore_tool_calls`** (default false): when
  true, only `user`, `assistant` and `runtime` messages are searched. A
  value other than a boolean is an error instead of being read as false.
- **Identical hits are folded.** Messages with the same kind, tool name and
  content appear once, with `duplicates=N`.
