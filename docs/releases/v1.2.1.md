# ZeroLite 1.2.1

ZeroLite 1.2.1 is a maintenance release over 1.2.0. It ships the same
`zeroclaw` binary, config file and command set, on upstream **ZeroClaw
v0.8.6**, with the WASM plugin host and the web dashboard embedded.

Release builds embed the web dashboard. Platforms: Windows x64, Linux x64,
Linux arm64. No macOS build.

## What changed since 1.2.0

### The context meter shows the real limit again

The web context ring showed **104,857** where the model side allows
**131,072**. The number was not a limit at all: it was the **water-line** —
the token count at which proactive trimming engages — which
`[context].trim_threshold_percent` (default 80) scales off the model's
window. The ring rendered a trigger as a cap.

Two things were wrong, and both are fixed:

- The ring took the water-line as its denominator. Its limit is now the
  **effective context window** — the model's capacity clamped by
  `[context].request_token_ceiling`.
- Neither field on the wire was the effective window, so a configured
  ceiling had no representation at all. The runtime now publishes
  `effective_context_window` (`model_window.min(request_token_ceiling)`) on
  the usage event, the WebSocket `done` frame and the RPC `context_usage`
  surface.

The ring's panel now shows both numbers, so they cannot be confused: the
**limit** (the effective context window) and the **trim trigger** (the
water-line).

### `[context].max_input_tokens` is now `[context].request_token_ceiling`

The field is a ceiling on request input tokens, not a window, and the old
name read as one. The new name says what it is.

```toml
[runtime_profiles.coder.context]
request_token_ceiling = 100_000   # hard ceiling on request input tokens (optional)
trim_threshold_percent = 80       # where history trimming engages (default: 80)
reserve_tokens = 16_384           # output headroom held back from the threshold (optional)
keep_recent_turns = 5             # preferred whole turns retained when trimming fires (default: 5)
```

This is a breaking config change: `max_input_tokens` is no longer accepted.
Update your `config.toml` before upgrading.

## Everything from 1.2.0

1.2.1 contains all of 1.2.0: the WASM plugin host
(`--features embedded-web,plugins-wasm-cranelift`), the restored context
engine, the web chat, session search, and `gateway.master_pair_code`.
See the [1.2.0 notes](https://github.com/iintothewind/zerolite/releases/tag/v1.2.0).

## Install

| Platform | Asset |
|---|---|
| Windows x64 | `zerolite-1.2.1-x86_64-pc-windows-msvc.zip` |
| Linux x64 | `zerolite-1.2.1-x86_64-unknown-linux-gnu.tar.gz` |
| Linux arm64 | `zerolite-1.2.1-aarch64-unknown-linux-gnu.tar.gz` |

Each binary carries the web dashboard and the WASM plugin host. Verify the
plugin host is present:

```sh
zeroclaw plugin list
zeroclaw status | grep -i plugin
```
