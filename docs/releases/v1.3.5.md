# ZeroLite 1.3.5

The `zeroclaw` CLI on the same upstream base as 1.3.4, ZeroClaw **v0.9.0**
(`6c78ba59b`). This release bounds the file tools by what they read and
return, and makes the history-trim notice honest and shown once. No config
or session-store migration: a 1.3.4 config and `sessions.db` are used as
they are. Platforms: Windows x64, Linux x64, Linux arm64. No macOS build.

## Before you upgrade

- **Upgrading from 1.3.3?** Run `zeroclaw config migrate` once (config
  schema version 4), as described in the 1.3.4 notes.
- **`file_edit` now replaces the file instead of rewriting it in place.**
  The edit is written to a temporary file in the same directory and renamed
  over the original, keeping its permission bits. The directory must be
  writable, and a hard link to the old file keeps the old content.

## File tools

- **`file_read` reads files of any size by line window.** File size no
  longer rejects a text read: `offset` and `limit` select lines, and only
  those lines are read into memory. Files up to 10 MiB report an exact line
  total as before; larger files end with `more lines follow`.
- **One `file_read` call returns at most about 48 KB**, less under a
  smaller `max_tool_result_chars`. The output is cut on a line boundary and
  ends with `continue with offset=N`, so the runtime's head/tail truncation
  no longer drops the middle of a read. A single line longer than the limit
  is cut and marked `…[truncated]`.
- **Binary files are detected from their first 8 KiB.** Text in a legacy
  encoding (Latin-1, Windows-1251) is now numbered per line and supports
  `offset`/`limit`; device files such as `/dev/zero` are refused instead of
  read without end.
- **`encoding="base64"` keeps its 10 MB cap**, now enforced on the bytes
  actually read.
- **`file_edit` refuses files over 10 MiB** and reads without following
  symlinks, through the same directory-handle helpers as `file_write`.
- **Delegate result files over 10 MiB are reported as unreadable** instead
  of loaded; the task's terminal status is unchanged.

## History trim

- **Each trim is announced once.** The durable trim no longer emits a
  second notice where before and after were equal.
- **The notice is one compact line** in the web dashboard and ZeroCode:
  `History trimmed: dropped N older turns, kept M · ~112.1K → ~24.2K tokens (budget 108K)`.
  Floor notices name the context window.
- **The numbers are honest:** the max-iteration trim labels each count with
  its own source, and overflow recovery prices the retried request (tool
  schemas, breadcrumb, a conservative margin) and marks unanchored counts
  as estimated.

## Install

| Platform | Asset |
|---|---|
| Windows x64 | `zerolite-1.3.5-x86_64-pc-windows-msvc.zip` |
| Linux x64 | `zerolite-1.3.5-x86_64-unknown-linux-gnu.tar.gz` |
| Linux arm64 | `zerolite-1.3.5-aarch64-unknown-linux-gnu.tar.gz` |

Each binary carries the web dashboard and the WASM plugin host
(`zeroclaw plugin list`). Replace the binary and restart the service.
