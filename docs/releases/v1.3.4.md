# ZeroLite 1.3.4

The `zeroclaw` CLI rebased on upstream ZeroClaw **v0.9.0** (`6c78ba59b`),
merged in full except two changes the fork does not take (see
[Not taken from v0.9.0](#not-taken-from-v090)). 1.3.3 sat on v0.8.6 with
selected later fixes. The fork's context engine, the WASM plugin host and
the web dashboard stay embedded. Same binary name, config path and command
set. Platforms: Windows x64, Linux x64, Linux arm64. No macOS build.

The config moves to **schema version 4**: run `zeroclaw config migrate`
once after upgrading. No session-store migration: a 1.3.3 `sessions.db` is
used as it is.

Upstream features that entered with this merge and have no fork precedent
yet (sign-in, account isolation, the relay dashboard, memory ownership,
the composition API) ship as upstream wrote them and are listed as
undecided in `zerolite_feature_list.md`.

## Before you upgrade

- **Run `zeroclaw config migrate` once** (config schema version 4,
  upstream #11218). Until then the config loads, migrated in memory, but
  `config set`, `config init`, `config patch` and `models set` refuse.
  - The first rewrite keeps the old file as `config.toml.v3.backup`
    (owner-only, readable by 1.3.3). **It still holds every retired key,
    including plaintext secrets.** Delete it once you no longer need to
    downgrade.
  - Retired keys: `[security.nevis]`, the eight agent-inline tunables
    (set them on `[runtime_profiles.<profile>]`), `summary_model`,
    top-level `[twitter]` and `[reddit]`, and `[channels.notion]`.
- **`[gateway.pairing_dashboard]` is now read** (#12213). A saved
  `code_ttl_secs` above 600 loads as 600 with a warning;
  `max_pending_codes` is dropped. Out-of-range values are refused at load:
  `code_ttl_secs` 30–600, `max_failed_attempts` 1–100, `lockout_secs`
  1–86400. The master pair code keeps working; its guard is built from the
  config with these limits.
- **Remote sessions nobody reconnects to close after 30 minutes**
  (#11964). Set `wss.orphaned_session_timeout_secs = 0` to keep them until
  the daemon restarts.
- **Under supervised autonomy, RPC `cron/add` and `cron/patch` refuse
  medium- and high-risk commands** (#11149). Jobs stored earlier fail on
  every tick with `requires explicit approval`; `cron list` shows them.
  Remove or patch them.
- **The filesystem channel refuses macOS and Windows system roots** too
  (#11406). A listener that stops with `path '...' is a broad system root`
  needs a narrower `paths`, or `allow_broad_roots = true` on that alias.
- **Accounts that are not administrators lose tools that act without
  knowing who asked** (#12232): SOP execution and decisions over RPC, cron
  agent jobs, peer turns, nested sub-agents and pipelines, saved daemon
  config and other accounts' sessions. In this fork that includes
  `session_search`. The single-operator setup is not affected.

## Sign-in and accounts (upstream, undecided here)

- **Dashboard sign-in through your own OIDC provider**, opt-in and off by
  default (`[gateway.dashboard_sign_in]` with `[oidc.<alias>]`). Pairing
  and the master pair code keep working beside it; an install without the
  new table behaves as before (#11965, #12233, #12157).
- **Scoped dashboard chat** for accounts that are not administrators,
  through the core RPC (#12244).
- **Account isolation:** a session's owner is re-checked when a change is
  written (#11234, #12239); delegated agents keep the owner's memory scope
  and owned sessions keep sub-agent and pipeline memory private (#11225,
  #11266); scoped accounts cannot read the daemon log (#11326).
- **ZeroCode** signs in with OIDC without pairing (`zerocode login`,
  #12317) and opens for accounts the daemon refuses Config or Logs
  (#12359); `/load-session` resumes a saved session (#12071).
- **Relay-served dashboard** (`[relay.dashboard]`, off by default,
  requires dashboard sign-in; #12270).

## Turns and runtime

- **Repeated tool failures are contained** in configured agent turns
  (#11507). The fork sends the mid-turn correction as a runtime
  `[Tool results]` message, so it is never shown or counted as your turn
  (`delegation-turn.md` R6).
- **Context-overflow errors report a breakdown** of what filled the
  request (#11578). The size the fork trims and meters on is unchanged;
  the breakdown is diagnostics only.
- **Claude 4.7 and later models get adaptive thinking**, including
  gateway-decorated names; older models keep the budget format (#12352).
- **No forced temperatures** in the post-turn skill review, the heartbeat
  decision step or the model-routing probe, so models that reject a
  temperature work there (#12363, #12368).
- **A tool call that cannot run in the session is refused before it asks
  for approval** (#12254).
- **Tool-result images move to a user message** on OpenAI-compatible
  endpoints that reject them in a tool result (`relocate` default, #10502).

## Channels

- **Signal** sends and receives photos, voice notes and documents (#11556).
- **Email** can run inbound-only without SMTP (#12003).
- **Telegram's** unauthorized-user notice is configurable
  (`unauthorized_message`, #11728) and its acknowledgement reaction is
  withdrawn when a reply finishes (#11739).
- **WhatsApp Web** renders horizontal rules and setext headings (#11054).
- Allowlisted Discord bots cannot answer tool approvals (#12065); "reply
  delivered" is logged only after the platform accepts it (#11979).

## Dashboard

- **A toolbar toggle keeps the live Thinking box collapsed** (#11920). In
  the fork it sits in the header icon group, and the header still fits a
  320px screen.
- **The in-flight prompt survives a reload** while the agent is still
  answering (#11571); the config form's Save stays inactive after the
  Enable/Disable pill saves (#12100); config pages are offered only to
  accounts that can read config (#12251).

## Security

- Wasmtime 48.0.8 (RUSTSEC-2026-0420 to -0424; `.cwasm` built for 48.0.7
  keeps working), `vodozemac` 0.11.2 (RUSTSEC-2026-0445, -0451, Matrix),
  `pulldown-cmark` 0.13.6 (RUSTSEC-2026-0414, -0433).
- OIDC enrollment: callbacks bound to the starting browser, the discovered
  authorization endpoint held to the URL policy, Basic credentials
  form-encoded, enrollment codes redeemed on the daemon's own guard.
- A bare `;` or `|` in an incoming message is no longer treated as command
  injection (#12068).
- Accepted with a tracking issue upstream: RUSTSEC-2026-0459 (bundled
  SQLite, local, needs a crafted database and `-wal` pair) and
  RUSTSEC-2026-0441 (`pin-utils` unmaintained).

## Not taken from v0.9.0

- **`keep_tool_context_turns` tool-context collapse** (#11297): the fork
  keeps whole tool results inside the window (`context-management.md`
  R1/R6/R8).
- **The built-in `zeroclaw-docs` skill** (#9579).
- **`zeroclaw update`, including `--standard`**, stays disabled on fork
  builds; upgrade by replacing the binary.
- Upstream's docs site, workflows, changelog and README changes; the
  desktop apps are not built by this fork.

## Known issues (from upstream v0.9.0)

- Sign-in is known to work only with Keycloak 26.8, self-hosted Zitadel
  v4.20 and Authelia 4.39; Google, Microsoft Entra ID, Okta, Amazon
  Cognito and Logto are not supported yet. No per-provider CA, configurable
  scopes or RFC 8707 `resource`.
- A provider outage at a session re-verification signs dashboard users out.
- The CLI's gateway admin commands (`gateway get-paircode`, `sop pending`,
  `logs`, `approve`, `deny`, `gateway restart`) always use `http://` and fail
  when the gateway serves TLS itself.
- A scoped account's dashboard chat ends with its connection.
- `zerocode login` to a second daemon detaches the first daemon's manual
  connection from its credentials (re-run `zerocode login` for it), and
  the connection editor can show the wrong TLS settings for a URL without
  its trailing slash.

## Install

| Platform | Asset |
|---|---|
| Windows x64 | `zerolite-1.3.4-x86_64-pc-windows-msvc.zip` |
| Linux x64 | `zerolite-1.3.4-x86_64-unknown-linux-gnu.tar.gz` |
| Linux arm64 | `zerolite-1.3.4-aarch64-unknown-linux-gnu.tar.gz` |

Each binary carries the web dashboard and the WASM plugin host
(`zeroclaw plugin list`). After installing, run `zeroclaw config migrate`
once, then restart the service.
