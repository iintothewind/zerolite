# ZeroLite 1.2.7

The `zeroclaw` CLI on upstream ZeroClaw **v0.8.6**, carrying the fork's context
engine, the WASM plugin host and the web dashboard embedded. Same binary name,
config path and command set. Platforms: Windows x64, Linux x64, Linux arm64.
No macOS build.

A patch release for the context ring: after a model switch it kept the previous
route's numbers until the turn ended. No config schema change — an existing
`config.toml` needs no migration.

## The ring follows the serving route

Three defects, one cause: the frames that price the request advertised limits
from the wrong place.

| Frame | Was | Now |
|---|---|---|
| `context_usage` (turn start) | the agent *profile's* limits, so a session running any model other than the profile's showed the profile's window | the routed pair's limits — the capacity the guard actually budgets against |
| `usage` (per call) | the three counters only; the window/budget the runtime had already stamped on the event was dropped when the frame was built | the serving route's `max_context_tokens` / `model_context_window` / `effective_context_window` ride along |
| `usage` for a rejected attempt | nulls in all three | the turn's accepted route: a rejected attempt has no window of its own, but its frame still closes a step |

What that buys: a mid-turn model switch (a tool asking for another route)
reaches `limit` / `trim budget` on the first post-switch call instead of on
`done`; a session whose selected model differs from the profile's shows its own
window at turn start; and a client that only adopts present fields can no longer
be handed a frame that blanks the snapshot.

The client folds the numerator, its provenance label and the route snapshot in
one reducer (`contextMeterStep`), so the four pricing frames cannot drift apart,
and a frame carrying no route fields leaves the current snapshot alone (older
daemons).

The reported case, end to end: `gemini-flash-lite-latest` (1,048,576 window →
838,860 budget) → `spark2-unsloth` (131,072 → 104,857) left the ring on
1,048,576 / 838,860 for the rest of the turn, while the guard had already been
budgeting 131,072 from the first post-switch dispatch.

## Fonts are self-hosted

The dashboard's CSP is `style-src 'self'; font-src 'self'`, while the theme
injected a `fonts.googleapis.com` stylesheet: every page load produced a blocked
request and the picked font silently fell back. Two of the eight picker options
were dead even without the CSP — Google answers 400 for `Segoe UI` and
`SF Pro Text`, which are OS-proprietary faces.

The four redistributable families now ship inside the binary as variable woff2,
`latin` subset only, each with its `OFL.txt`:

| Family | Size |
|---|---|
| Inter | 48,256 B |
| JetBrains Mono | 40,404 B |
| Fira Code | 36,276 B |
| Cascadia Code | 48,600 B |

173,536 B in total (+192 KB on the binary). A page fetches only the family in
use — the default pulls JetBrains Mono's 40 KB; the settings dialog pulls all
four because it previews every option. `Segoe UI` and `SF Pro Text` stay system
stacks, which is all they ever were.

None of the four carries CJK glyphs, and the `unicode-range` says so: Chinese
resolves to the platform face, now named explicitly in both stacks (`PingFang
SC`, `Hiragino Sans GB`, `Microsoft YaHei`, `Noto Sans CJK SC`, `Source Han Sans
SC`). The mono stacks had no CJK entry at all, so Chinese inside code blocks fell
to the generic `monospace` CJK — a Song-style face on Windows. Checked by
per-glyph resolution: `abcABC123 中文测试` in the mono stack renders 10 glyphs
from JetBrains Mono and 4 from Noto Sans CJK SC.

## No more "Config changed — reload daemon to apply"

Every config save raised the gateway's `pending_reload`, and the layout banner
showed it. A model switch is a config save, so a routine action answered with a
reload prompt for a change the runtime applies on the next turn anyway — and a
reload tears down every channel.

Both ends changed:

- the gateway no longer raises the flag for `agents.<alias>.model_provider`
  (`config_write_needs_reload`). Every other path, including a whole-config save
  that records no per-path entry, keeps the conservative answer;
- the banner reports only on-disk drift — the config file diverging from what the
  daemon loaded, which only an external edit produces and which a reload really
  fixes. The Config page keeps its reload action, and the drift banner still
  offers it.

## Build notes

- **Upgrading a running host:** hard-refresh the dashboard once — the bundle
  hash changed. A dashboard served from `<data>/web/dist` is never used by this
  build (`embedded-web` outranks it).
- **Verification for this release:** `zeroclaw-runtime` lib 5813 passed
  (8 ignored), `zeroclaw-gateway` lib 687, the web suite green, `npm run
  typecheck` (with `check:generated`) clean, `cargo fmt --all --check` clean, and
  no new clippy warnings in the touched crates.
- New coverage worth naming: the turn-start frame advertises the routed limits
  rather than the profile's; the `usage` frame carries the serving route's
  window; two calls across an in-turn route switch move both the frame and the
  terminal snapshot; a rejected attempt's frame keeps the accepted route's
  window; and a model selection write raises no `pending_reload` while a
  `gateway.port` write still does.
- The arm64 artifact deployed to a test host was built from this tree with
  `embedded-web` (`assets/index-BYi2YblM.js`), `sha256 59aa3c76…`, 45,328,800 B;
  CI builds the release assets from the tag.
