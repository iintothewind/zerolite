# ZeroLite 1.3.3

The `zeroclaw` CLI on the same upstream base as 1.3.2 (ZeroClaw **v0.8.6**,
the v0.8.7 fixes and the selected later fixes, upstream master pinned at
`4b11ce6d2`). The fork's context engine, the WASM plugin host and the web
dashboard stay embedded. Same binary name, config path and command set.
Platforms: Windows x64, Linux x64, Linux arm64. No macOS build.

A fix release: a model that answers with nothing no longer ends the turn
silently, prompts the runtime writes stop showing up as your own messages
after a reload, and the dashboard fits a phone screen. No upstream code is
added. No config schema change and no session-store migration: an existing
`config.toml` and a 1.3.2 `sessions.db` are used as they are.

## Turns

- **An empty final reply no longer ends the turn.** A reply with no tool
  call whose text is empty, whitespace, think-only or a lone `.` is rejected
  and never stored. The provider retry policy runs first; once it is
  exhausted, the agent is told once that nothing was delivered and asked to
  answer or continue. A second empty reply in a row fails the turn with the
  explicit empty-completion error instead of a blank answer. At most three
  such nudges per turn. Observed with a local model that writes `.` beside
  every tool call: whenever the tool call was missing, the turn ended on
  the `.`.
- **Prompts the runtime writes are no longer stored as your messages.** The
  prompt sent when a turn hits its tool-iteration or execution-tree limit,
  and the feedback after a malformed tool call, are now hidden `runtime`
  rows. Before, a reloaded turn that had hit the iteration limit showed an
  `Agent exceeded maximum tool iterations` user bubble that split the turn
  into a tool group and a detached answer. These prompts no longer count as
  turn boundaries either, so `keep_recent_turns` counts the turns you see.
  Applies to turns stored from 1.3.3 on; rows already stored are not
  rewritten.
- **SOP step contexts** are stored as `runtime` rows too and stay turn
  boundaries: a long SOP run still trims on them.

## Dashboard

- **The mobile shell fits the visible screen.** Heights follow the visible
  viewport (`dvh`), so dragging the header or the composer no longer scrolls
  the whole page. No rubber-band or pull-to-refresh, no sideways panning,
  and pinch / double-tap zoom is off. Controls are at least 16px on touch
  devices, so iOS does not zoom on focus. While the on-screen keyboard is
  up, the shell follows the visual viewport and the header stays visible.
  The transcript keeps following the newest message when the viewport
  resizes. The chat toolbar and the session menu fit a 320px screen.
- **The tool-activity toggle shows its state.** The wrench button reads in
  the accent colour while tool activity is shown; the mobile menu item gets
  an accent icon and a check.
