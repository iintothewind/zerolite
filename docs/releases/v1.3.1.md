# ZeroLite 1.3.1

The `zeroclaw` CLI on upstream ZeroClaw **v0.8.6**, the v0.8.7 fixes 1.3.0
carried, and **selected later upstream fixes** (upstream master pinned at
`4b11ce6d2`). The fork's context engine, the WASM plugin host and the web
dashboard stay embedded. Same binary name, config path and command set.
Platforms: Windows x64, Linux x64, Linux arm64. No macOS build.

A fixes-only release. Each upstream fix was cherry-picked on its own
(`merge-2026-11-09`). None touches the fork's context management, meter,
session search, delegation, provider compatibility or web UI. No config schema
change: an existing `config.toml` needs no migration. Three behaviours change
for operators; see **Before you upgrade**.

## Before you upgrade

- **Shell policy now looks inside substitutions and subshells.** A command
  inside `$(…)`, backticks or `( … )` is split out and checked against the
  allowlist and risk rules like any other command (upstream #11822). A
  command line that passed before because the forbidden part sat inside a
  substitution is now refused. Heredocs whose delimiter is ambiguous, or
  ANSI-C quoted (`$'…'`), are refused.
- **`firejail_args` now apply, and invalid ones block commands.** Configured
  `firejail_args` are passed to Firejail before the wrapped command
  (upstream #11656). Before, they were silently dropped. If Firejail is the
  selected sandbox and its configured arguments are rejected, every command is
  refused with the reason, rather than running without them.
  `zeroclaw security status` reports the rejected arguments. A config without
  `firejail_args` behaves as before.
- **Turns a killed process left running are marked failed.** When a process
  first takes ownership of a data directory, session rows still marked
  `running` by a process that died (`kill -9`, crash, power loss) become
  `error`, once, with a WARN record ("marked session turns left running by a
  previous process as failed"). A config reload never touches live turns
  (upstream #11523).

## Gateway

- **WebSockets work over the native TLS listener.** With `[gateway.tls]`
  enabled, the dashboard's chat socket (and every other WebSocket route)
  failed: the TLS listener served HTTP without upgrades, so the socket closed
  right after the handshake. It now upgrades as over plain HTTP (the TLS part
  of upstream #11965).
- **A stopping gateway drains its connections.** On `/admin/reload` or
  shutdown, the old instance releases its port at once, admits no new
  request (`503 {"reason":"gateway_restarting"}`, GOAWAY on HTTP/2), lets
  requests in flight finish, and closes what is left within 300 ms. Before,
  connections the old instance had accepted (on the TLS listener in
  particular) could outlive it (upstream #11901).
- **Rate-limit key behind a proxy.** With trusted-proxy mode, the per-client
  key comes from the hop the proxy appended (rightmost `X-Forwarded-For`
  entry), not a client-supplied leading entry. A loopback-only forwarded
  value no longer inherits the loopback exemption (upstream #12114).

## Runtime and storage

- **Concurrent first opens of a fresh session store succeed.** Two processes
  opening a new `sessions.db` at the same time no longer race on schema
  creation; the daemon retries a failed store open once (upstream #11900).
- **Bubblewrap rejection names its cause** — not compiled in, launcher probe
  failed, or the requested backend unavailable (upstream #11559).
- **MCP tool listings are name-sorted**, so a server's insertion order does
  not move the prompt-cache prefix (upstream #12177; fork prompt-cache R2).
- **Windows:** the model cache (`/model`) and a JSONL session file are
  replaced even while a reader holds them open (upstream #11400, #11398).

## Plugin host fixes

- **A component is admitted only beside the manifest that described it.** A
  package republished between reading its manifest and loading its component
  is refused at admission and skipped by discovery (upstream #12040).
- **Abandoned install stages are cleared by the next install** of the same
  name, without touching other names, stages another host holds, or a stage
  the install is reading from (upstream #11855).
- **Sender-denial records name the sender** (bounded) for channel plugins
  (upstream #11848).

## Memory

- **Credential-in-URL scan narrowed.** Only URLs with userinfo
  (`user:pass@`) or a credential-named query/fragment parameter with a value
  are flagged; a plain URL beside the word "password" in prose is not
  (upstream #11144).
- **Qdrant search honours time bounds.** `since`/`until` become a
  `timestamp` range filter on vector search (upstream #11143).
