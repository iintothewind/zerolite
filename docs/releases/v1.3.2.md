# ZeroLite 1.3.2

The `zeroclaw` CLI on the same upstream base as 1.3.1 (ZeroClaw **v0.8.6**,
the v0.8.7 fixes and the selected later fixes, upstream master pinned at
`4b11ce6d2`). The fork's context engine, the WASM plugin host and the web
dashboard stay embedded. Same binary name, config path and command set.
Platforms: Windows x64, Linux x64, Linux arm64. No macOS build.

A fork feature release: the dashboard chat transcript is now a complete,
append-only history. Tool calls and their output are stored, a context trim
no longer deletes anything, history is read in pages of turns, and session
search matches Chinese/Japanese/Korean substrings and tool output. No
upstream code is added. No config schema change: an existing `config.toml`
needs no migration. The **session store** is migrated; see **Before you
upgrade**.

## Before you upgrade

- **Back up `sessions.db`; there is no downgrade.** On first open, 1.3.2
  migrates `<data_dir>/sessions/sessions.db` to schema version 2 (`PRAGMA
  user_version = 2`): new row columns, and the full-text index is rebuilt in
  a new format. A 1.3.1 binary cannot write to a migrated store. To roll
  back, stop the daemon and restore the backup.
- **The first start takes longer on a large store.** The migration
  re-indexes every stored message once, inside the store's opening
  transaction. Later starts are unaffected.
- **Earlier history is what it was.** Turns stored before the upgrade keep
  their chat messages only: tool calls were never stored, and turns an
  earlier trim deleted are gone. Everything from the first 1.3.2 turn on is
  kept whole.
- **`GET /api/sessions/{id}/messages` changed shape.** It returns a page of
  whole turns (newest 20 by default, `?before_turn=&turns=`, at most 200),
  and every row carries `id`, `turn`, `kind`, `content_bytes`, `tool_name`,
  `tool_call_id`. Tool output is `null` in a page; fetch it with the new
  `GET /api/sessions/{id}/messages/{message_id}`. The `synthetic` field is
  gone (`kind: "runtime"` replaces it). A script that read the whole
  transcript in one call must page now.

## Dashboard chat transcript

- **Every turn is stored whole, once, when it ends** (answer, Stop, or
  error): your message, the agent's narration between tool calls, each tool
  call with its arguments, each tool result, and the answer. Each row gets the
  turn's number (dense from 1 per conversation).
- **A context trim no longer deletes history.** The agent still drops old
  turns from what it sends the model; the store only records where the
  agent's context now starts. Reconnecting or restarting restores exactly
  that context: the chat messages from that point on, without tool rows. The
  dashboard's trim notice and local cut behave as before, and the trimmed
  turns can be loaded back.
- **The dashboard loads the newest 20 turns.** `Load earlier turns` above
  the first turn prepends the previous 20 and keeps your reading position.
  The composer's turn count counts the turns on screen.
- **Reloaded turns show their tool calls.** A reloaded turn folds into the
  same collapsed `N tool calls · M messages` group a live turn gets (1.3.1
  could only show the answer for gateway-stored turns). Tool output is
  fetched when you expand the group (`Loading output…`, then the output).
- **Every stored row's `created_at` is kept.** Rewrites used to restamp
  the whole transcript on every turn.

## Session search and history tools

- **`session_search` is back in the agent tool set.** Its registration and
  per-agent ownership scoping were lost in the upstream v0.8.6 merge
  (since 1.1.0); an agent again searches only its own sessions and its
  channels' sessions.
- **Chinese, Japanese and Korean text matches by substring.** `查询` finds
  `数据库查询效率`. Before, a CJK run matched only as a whole.
- **Tool calls and tool results are searched.** A tool call matches by tool
  name and by anything in its arguments. Each hit reports `turn`, `kind`
  (`user`, `assistant`, `runtime`, `step`, `tool_call`, `tool_result`) and
  `tool`, and its snippet marks the match with `<b>…</b>`.
- **Search stays fast on a large store.** Hits are read newest first
  straight off the index and stop at the limit: a common term over a few
  hundred MB of tool output answers in under a millisecond instead of
  sorting every match.
- **`sessions_history` reads tool rows on request.** `include_tools: true`
  adds tool calls and results (default off). An anchored read
  (`around_message_id`) always starts with the user message of the anchor's
  turn. A tool row's body is shown 50 lines at a time, each line cut at
  2000 characters; a cut body ends with the `line_offset` that continues it
  (`line_offset` / `line_limit`).
- **Channel sessions** (Telegram etc.) store chat messages as before;
  tool rows and turn paging are gateway-chat only. Their messages are in the
  new index, so CJK search works for them too.
