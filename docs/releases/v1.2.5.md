# ZeroLite 1.2.5

The `zeroclaw` CLI on upstream ZeroClaw **v0.8.6**, carrying the fork's context
engine, the WASM plugin host and the web dashboard embedded. Same binary name,
config path and command set. Platforms: Windows x64, Linux x64, Linux arm64.
No macOS build.

## The context engine

**One trigger: replayed tokens past the water-line.**

```text
trim_threshold = min(window × trim_threshold_percent / 100,
                     window − reserve_tokens)        # reserve term omitted when unset
```

Nothing else starts a trim — not the turn count, not a message cap, not
`keep_recent_turns`, which is what a trim *keeps*.

**Two decision points, two kinds of evidence.** Before a request leaves, no
report for it exists and none can, so the local estimate is the only evidence —
and it is the trigger. After a reply lands the billed `usage.input_tokens`
exists, so the estimate stops acting on its own; if the request could not fit at
all, the overflow guard fires against `send_budget = window − reserve_tokens`
rather than the raw window, so `request_token_ceiling` is honoured.

**A trim drops whole turns.** Keep the newest `keep_recent_turns`, cascade down
until the set fits `send_budget`, fail the turn if even one turn does not fit.
A turn is never split and the newest is never dropped.

**No compaction, no off switch.** Nothing summarizes history or rewrites it into
a surrogate; a shrinking history is always dropped turns. A disabled trim would
let the request exceed the window and fail at the provider, where the cause is
no longer visible. Both are recorded decisions (R6, R7) in
`docs/design/context-management.md`.

```toml
[runtime_profiles.coder.context]
request_token_ceiling = 100_000   # optional; clamps the effective window
trim_threshold_percent = 80       # water-line, default 80
reserve_tokens = 16_384           # output headroom, optional
keep_recent_turns = 5             # preferred whole turns, default 5 (clamped 1–10)
```

| Field | Default | Meaning |
|---|---|---|
| `request_token_ceiling` | unset | Ceiling on request input tokens. Clamps the effective window (`model_window.min(ceiling)`), which is also the meter's denominator. Does not trigger trimming by itself. |
| `trim_threshold_percent` | `80` | Percentage of the effective window at which trimming engages. `1..=100`; anything else is a hard config error. |
| `reserve_tokens` | unset | Output headroom. Bounds the water-line and defines `send_budget`. At most half the effective window. |
| `keep_recent_turns` | `5` | Preferred whole turns retained. `1..=10`; cascades down to one if they do not fit. |

`[context].max_input_tokens` is not accepted; use `request_token_ceiling`.

## The context meter

The ring used to lag a turn behind: a trim fired, the ring kept the pre-trim
number, and only the final frame corrected it. It now moves when the turn moves.

| When | What the client receives | Label |
|---|---|---|
| The turn starts, after the water-line decision | assembled request size | `estimate` |
| A trim fires mid-turn | `tokens_after` on `history_trimmed` | `estimate` |
| A provider call returns | that call's `input_tokens` | `provider` |
| The turn ends | `last_input_tokens` on `done` | `provider` |

Two properties are deliberate. The pre-send number travels as `context_usage`,
not `usage`, because clients fold `usage` into their step boundary and "a
request is about to go out" is not "a call completed". And every estimate is
labelled, because the local estimator over-counts CJK-heavy text (0.44–0.95
tokens per character against a flat 1.0 charge).

The trim itself is unchanged — same trigger, same keep-N action, same cascade.
Display plumbing only, so cache economics are untouched.

### What the review changed

Nothing behavioural; three claims were wrong and are now right.

- **The ordering guarantee was documented as something it is not.** The design
  doc said these frames "carry the turn's identity"; they carry no turn id at
  all. What holds the meter steady is ordering plus serialization: the
  per-session actor queue admits one turn at a time, a turn's frames go out in
  order, and `done` wins. The doc now says that, and names `turn_id` on
  `context_usage` and `history_trimmed` plus a per-turn monotonic guard as a
  prerequisite for concurrent turns or reconnect replay.
- **Two budgets read as one.** `context_token_budget` / `max_context_tokens` is
  the **water-line** — when a trim engages. `token_budget` on `history_trimmed`
  is the **send budget** — how small the trim was asked to make the request. The
  comment claiming the water-line could be `None` "when trimming is disabled"
  described an unreachable state: the percent is clamped to `1..=100` and the
  budget takes `.max(1)`. Both comments now name their number, and the design
  doc has a table putting them side by side.
- **The chain had no test walking it.** Two do now.
  `a_streamed_turn_publishes_the_trim_before_the_provider_usage` (runtime)
  drives a real streamed turn and asserts `history_trimmed` → `context_usage` →
  `usage`, with `tokens_after < tokens_before` and both labelled `estimate`.
  `trimmed_frame_carries_the_post_trim_estimate_and_its_source` (gateway) pins
  `tokens_after` on the frame and that it fits the send budget the same frame
  advertises. The socket hop itself is still untested — it is the same
  `sender.send` for every frame type.

## Renamed and restored

- `[runtime_profiles.<alias>].compact_context` is now `lean_bootstrap`, default
  unchanged (`true`). It never compacted anything: it caps each injected
  bootstrap file at 6000 characters, limits RAG recall to two chunks and skips
  the full Channel Capabilities copy. The old key is **not** accepted — a config
  still writing it is read as absent and silently gets `true`.
- `[gateway].master_pair_code` reaches every gateway path again, including
  `zeroclaw service start`. Submitting it on the pairing page or to
  `POST /api/pair` mints a bearer token without consuming the one-time code. It
  is reusable, never printed, inert while `require_pairing = false`, and a value
  that collides with the live one-time code consumes that slot.

## Upgrading

The binary name, config path and command set are unchanged.

- Rename `[context].max_input_tokens` → `[context].request_token_ceiling`.
- Rename `compact_context` → `lean_bootstrap`.
- If you relied on the runtime stamping today's date into the prompt, move that
  into `AGENTS.md` — nothing in the runtime injects a date any more.
- Structured-log parsers: the channel overflow attribute is `history_trimmed`
  (was `history_compacted`), and the user-facing message says "I trimmed recent
  history".

Upstream v0.8.6 changes most likely to bite:

- Pairing codes default to 32 characters, and reading or minting them needs the
  gateway admin token. Set `[gateway.pairing_code] length = 6, charset = "numeric"`
  for the old shape.
- Remote WSS needs `auth_token`; `[security.nevis]` is retired in favour of
  `[oidc.<alias>]`.
- `[browser] enabled = true` no longer implies the `browser` tool; set
  `browser.automation_enabled = true`.
- `file_download` refuses private-network hosts unless listed in
  `[file_download] allowed_private_hosts`.
- Full autonomy no longer overrides `always_ask`.
- The shell follows the platform default; pin it with `runtime.shell = "sh"` or
  `"cmd"`.

Upstream notes: <https://github.com/zeroclaw-labs/zeroclaw/releases/tag/v0.8.6>

## Fixed defects

- **The meter and the water-line priced messages but not tool definitions.** A
  request is `messages + tools` and providers bill both, so every count that
  omitted the schemas was short by the whole tool catalog. The dashboard's meter
  dropped by that much the moment a turn started and climbed back when `usage`
  arrived; the water-line fired a catalog late, so `trim_threshold_percent = 80`
  behaved like 80% *plus* the catalog. The assembled estimate, the trigger and
  the trim target now price the same population, and the trim notice reports the
  provider-facing size.
- **The context meter lagged a turn behind after a trim.** The runtime knew the
  post-trim size, but the notice it forwarded hardcoded `tokens_before: None,
  tokens_after: None`, so the frame carried no numbers. It now carries both
  counts plus the send budget, labelled `estimate`.
- **Wall-clock time was stamped into the prompt at six sites** — user turns, the
  delegate sub-agent prompt, the channel turn-context preamble and two loop
  paths. Each stamp was replayed into every later request. All six are gone, so
  the prefix stays byte-stable (decision R1); display-only strip helpers still
  recognise the legacy prefixes in old transcripts.
- **The trim breadcrumb lost its ownership across a restart.** Whether a
  transcript opened with the synthetic breadcrumb was never persisted, so a
  restarted process could not tell machinery from a first user turn and trimmed
  again on every reconnect. It is a one-byte sidecar next to the transcript now,
  and anything but `0`/`1` fails closed. Transcripts written before the sidecar
  no longer get guessed at from row position: provenance resolves to `false`,
  and the next trim writes the flag.
- **A restored session replayed one row too few**, because the breadcrumb was
  counted as a dropped message. It is excluded from both the keep-N slots and
  the dropped count now.
- **A failed Edge TTS read left its temp file behind.** Temp file, child and
  output are owned by one RAII guard, so every failure path reaps before it
  deletes.
- **An exited process was reported as alive.** The descendant check used a
  signal probe, which also succeeds for an unreaped zombie; it reads the process
  state from the kernel now.
- **The dashboard's session-lifecycle suite could not mount**, because the test
  harness lacked `getBoundingClientRect`. The harness covers it, and a test
  asserts it keeps pace with the transcript pane.

## Build notes

- **CI actions on Node 24.** `checkout@v7`, `setup-node@v7`,
  `upload-artifact@v7`, `download-artifact@v8`, `setup-python@v7`,
  `softprops/action-gh-release@v3`, `docker/setup-qemu-action@v4`.
  `Swatinem/rust-cache@v2` already resolves to Node 24. Runners must be
  **2.327.1 or later**.
- **Local cross builds skip apt.** `scripts/dev/build-cli-local.sh` probes the
  image for `aarch64-linux-gnu-gcc` and installs nothing when it is already
  there. `dev/cross/Dockerfile` bakes that toolchain into an image CI publishes
  as `ghcr.io/iintothewind/zeroclaw-cross-aarch64:bookworm`; pass it with
  `--image` and a build needs no network beyond the pull.
