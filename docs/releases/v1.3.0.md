# ZeroLite 1.3.0

The `zeroclaw` CLI on upstream ZeroClaw **v0.8.6** plus **twelve selected v0.8.7
fixes**, carrying the fork's context engine, the WASM plugin host and the web
dashboard embedded. Same binary name, config path and command set. Platforms:
Windows x64, Linux x64, Linux arm64. No macOS build.

This release adds upstream security and bug fixes. It does not adopt v0.8.7 as a
whole. The twelve fixes were cherry-picked one by one (`merge-v0.8.7`). None
touches the fork's context management, meter, session search, delegation,
provider compatibility or web UI. No config schema change: an existing
`config.toml` needs no migration. Two behaviours do change for operators: where
the config lifecycle lock lives, and MQTT keep-alive validation (see
**Before you upgrade**).

## Before you upgrade

- **Stop every running `zeroclaw daemon`, `agent` and `acp` process before you
  install this binary.** The config lifecycle lock moved from
  `<data>/config-lifecycle.lock` to `<data>/.lifecycle/config-lifecycle.lock`.
  An old process and a new one do not see each other's lock, so they would not
  exclude each other.
- **A data directory once touched by `sudo` is now refused, not silently
  shared.** The lock directory must belong to the user running ZeroClaw and
  must not be writable by its group or by others. If it is root-owned, owned by
  another account, or group/world-writable, startup stops and prints the exact
  `chown`/`chmod` command to fix it. An existing shared data directory is
  accepted unchanged; only `.lifecycle` is held to owner-only.
- **MQTT:** `keep_alive_secs` must fit MQTT 3.1.1's 16-bit field (0–65535).
  The new client takes it as a `u16`, so a larger value is now rejected when
  the channel builds its MQTT options.
- **Plugins:** Wasmtime moves to 48.0.7. Registry `.wasm` packages are
  JIT-compiled on load and need nothing. A precompiled `.cwasm` built for an
  older Wasmtime must be rebuilt.

## Security advisories cleared

The upstream fix removes four `.cargo/audit.toml` ignores (RUSTSEC-2026-0049,
-0098, -0099, -0104); the two later bumps clear RUSTSEC-2026-0385 and -0386.

| Area | Change |
|---|---|
| WASM plugin host | `wasmtime`, `wasmtime-wasi`, `wasmtime-wasi-http` 48.0.6 → **48.0.7** |
| TLS | `rustls-webpki` 0.102.8 / 0.103.15 → **0.103.16** (one version left); `webpki-roots` 1.0.9 / `webpki-root-certs` 1.0.7 → 1.0.10 |
| MQTT channel | `rumqttc` 0.25.1 → **`rumqttc-v4-next` 0.34.0**; `rumqttc` was the only consumer of `rustls-webpki` 0.102.8 |
| Constant-time / runtime | `ctutils` 0.4.2 → **0.4.5**, `tokio` 1.53.1 → **1.53.3** (RUSTSEC-2026-0385, -0386) |

The MQTT client swap keeps the channel's behaviour and adds tests for it
(`orchestrator::mqtt::security_tests`):
- default TLS rejects an untrusted CA;
- a trusted CA with the wrong hostname is still rejected;
- a TLS listener never reconnects over plaintext;
- MQTT 3.1.1 credentials, keep-alive and every subscription QoS survive the
  swap.

`Cargo.lock` was resolved against the fork's own lock. Only the versions these
fixes require changed; every other fork pin stays.

## Gateway: a reload no longer strands chat sockets

After `/admin/reload` (or any config reload that replaces the gateway instance),
WebSocket chats opened on the old instance stayed attached to it. They then
talked to a retired gateway. Those sockets now close with **1001 "gateway
restarting"** so the client reconnects to the live instance. The socket closes
only between turns: a turn already running finishes first. The fork's
detach-mid-turn path is unchanged, so a client that drops mid-turn still leaves
the turn running and gets its history on reconnect.

## Plugin host fixes

- **Egress declarations count every governed transport.** A tool package that
  reaches a host only over WebSocket or raw sockets now has that destination
  declared, seeded and asked about at install. Before, only HTTP rows counted.
- **A silent address cannot stall a pinned connect.** When a pinned egress host
  resolves to several addresses, dials are staggered and interleaved across
  IPv4/IPv6. A blackholed first address no longer holds up a reachable second
  one. A TLS failure is reported in preference to a later connect failure.
- **Package lock and transaction leases are owner-only.** They are created with
  owner-only permissions. A lock this account cannot open fails at once and is
  named.
- **`zeroclaw config set` takes non-secret plugin settings as given.** A setting
  the package declares without `x-secret` is plain input and needs no terminal.
  Secret and undeclared settings stay masked.
- **Host tool names are reserved before plugin tools register.** Peripheral,
  skill and MCP capability tools reserve their names first, so a plugin tool
  claiming one of them is refused. The prompt's tool block stays name-ordered:
  registration order does not move the prompt-cache prefix (pinned by
  `tool_specs_follow_name_order_not_registration_order`).
- **`zeroclaw plugin remove` deletes the directory the package was loaded
  from.** A package that changed after this host loaded it is refused. A
  directory or symlink swapped in at the name is put back. A remove interrupted
  after its claim is finished by the next remove.
- **`plugin info` and `plugin list --verify` report the runtime's config
  verdict.** A tool whose `[[plugins.entries]]` `config` the runtime would
  refuse now shows `Loads: no`, with the runtime's error and the entry to fix
  against the package's `config_schema`. A refused configuration is no longer
  reported as a load failure.

## Dashboard: markdown images over plain http

The dashboard CSP admitted `https:` images only, so a markdown image served by a
LAN or private service over `http` (an artifact URL on `10.x`, say) was blocked.
`img-src` now also admits `http:`. `https:` already admitted any host, so the
tracking/exfiltration surface does not grow (webui R4 / behaviour #6).
